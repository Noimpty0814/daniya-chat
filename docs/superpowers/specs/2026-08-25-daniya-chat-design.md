# 达妮娅聊天（Daniya Chat）设计文档

日期：2026-08-25
状态：已与用户逐节确认（架构 / 桌宠联动 / 聊天功能与数据）

## 1. 背景与目标

用户想要一个桌面聊天软件，接入 DeepSeek API 进行对话，保存聊天历史；并与用户的桌宠"达妮娅"联动：

1. 点击桌宠 → 弹出/激活聊天框
2. AI 回复时 → 桌宠做出对应表情（如高兴=彩虹脸、难过=哭泣脸）
3. 支持截屏发送给 AI（"让 AI 看到屏幕"）

## 2. 桌宠分析（达妮娅 = Bongo Cat Mver 改版）

位置：`E:\迅雷下载\达妮娅-带表情版\A-达妮娅\`

## 3. 整体架构

```
┌─ Electron 主进程 (Node.js，默认非管理员) ─────────────┐
│ ・DeepSeek API 调用（OpenAI 兼容，SSE 流式，fetch 实现）│
│ ・聊天历史存储（本地 JSON 文件）                       │
│ ・截屏（desktopCapturer → PNG → base64）              │
│ ・API Key 用 safeStorage 加密保存                     │
│ ・桌宠联动协调（与助手进程通过命名管道通信）            │
├─ preload 桥接层 ─────────────────────────────────────┤
│ ・contextBridge 暴露类型安全 IPC 接口                  │
└─ 渲染进程 (React + TypeScript) ──────────────────────┘
   聊天界面：会话列表/消息区/输入框/设置页

┌─ 桌宠联动助手（隐藏 PowerShell 子进程，按需运行）──────┐
│ ・WH_MOUSE_LL 全局鼠标钩子：点击落在桌宠窗口矩形内 → 通知主进程 │
│ ・接收命令：向桌宠窗口发送 Alt+组合键（激活+keybd_event）│
│ ・检测桌宠是否以管理员运行；若是，助手弹一次 UAC 提升自身 │
└──────────────────────────────────────────────────────┘
```

### 数据流

1. 用户发消息 → 渲染进程先显示并落盘 → 主进程流式调用 DeepSeek → 逐字渲染 → 完成后整条落盘
2. 消息带截屏 → 该请求路由到视觉模型 `deepseek-v4-flash-vision-exp`；纯文字 → 文本模型 `deepseek-chat`
3. 点击桌宠 → 助手经命名管道通知 → 主进程在桌宠旁显示聊天窗口并聚焦；再次点击/Esc 收起
4. AI 回复含情绪标记 → 主进程解析后经管道命令助手发送 Alt+组合键 → 桌宠表情
5. 等待回复期间 → 桌宠"泡泡出现"（Alt+0）；完成 → 泡泡消失（Alt+-）

### 关键设计决定

- **API 调用在主进程**：Key 只存在于主进程，渲染进程永远接触不到明文 Key
- **不用任何原生 Node 模块**：联动逻辑全部由 PowerShell 助手承担（Windows 自带 .NET/WinForms），避免 electron-rebuild 编译风险
- **聊天主功能与桌宠联动解耦**：助手未运行/桌宠未启动时，聊天、历史、截屏全部正常工作，只是跳过表情联动

## 4. DeepSeek API 集成

- 接口：OpenAI 兼容 Chat Completions，`base_url` 默认 `https://api.deepseek.com`，设置页可改（支持中转）
- 文本模型：默认 `deepseek-chat`（设置页可切换，如 deepseek-reasoner）
- 视觉模型：`deepseek-v4-flash-vision-exp`（2026-08-21 上线，图片以 base64 data URL 内联，仅允许出现在 user 消息中；纯文本模型收到图片会 400）
- **路由规则**：当前消息含图片，或历史中已有图片（保持上下文可见）→ 视觉模型；否则 → 文本模型
- 流式：`stream: true`，解析 SSE `data:` 行，`delta.content` 增量渲染
- 情绪标记：系统提示词要求模型**在回复第一个 token 输出** `{EMO:<emotion>}` 标记（其前无空格无换行）。主进程对流式增量做前缀匹配：已累积文本以 `{EMO:` 开头时暂缓渲染，直到收到 `}` 完成解析；解析出的情绪用于桌宠联动，标记本身不进入显示文本与落盘内容；若整个回复结束仍未出现合法标记，视为无情绪（默认表情），文本原样显示

| 情绪 | 桌宠表情 | 按键 |
|---|---|---|
| happy | 彩虹脸 | Alt+I |
| sad | 哭泣脸 | Alt+O |
| sleepy | 瞌睡脸 | Alt+P |
| dismissive | 不屑脸 | Alt+U |
| shy/blush | 鼻血脸 | Alt+Y |
| angry/dark | 黑化形态 | Alt+1 |
| 无标记 | 默认表情 | Alt+D |

## 5. 界面与功能

```
┌──────┬──────────────────────────┐
│ 会话  │  消息区（Markdown+代码高亮）│
│ 列表  │                          │
│ +搜索 │                          │
│      ├──────────────────────────┤
│      │ 输入框   [截屏] [发送]     │
└──────┴──────────────────────────┘
```

- **多会话**：新建/切换/重命名/删除，按最近活动排序
- **流式输出**：打字机式逐字渲染，可中途"停止"
- **Markdown 渲染**：react-markdown + remark-gfm + highlight.js 代码高亮，代码块一键复制
- **历史搜索**：全局搜索全部会话内容，命中结果跳转对应会话
- **截屏**：截取屏幕 → 输入框内缩略图预览（可取消）→ 随消息发送；截屏消息用视觉模型
- **窗口联动**：点击桌宠弹出窗口，位置在桌宠旁边；Esc/再次点击收起
- **设置页**：API Key（safeStorage 加密保存）、文本/视觉模型选择、Base URL、桌宠路径（默认自动探测）、联动开关、情绪映射编辑、**DeepSeek Key 申请图文指引**（内置静态页面）

## 6. 数据存储

- 位置：`%APPDATA%/daniya-chat/`（不动桌宠目录）
- 格式：`index.json`（会话元数据）+ `conversations/<id>.json`（消息数组），纯文本可备份迁移
- 消息结构：`{ id, role, content, images?, createdAt, model, emotion? }`
- 搜索：加载时建立内存索引（简单子串匹配），个人使用规模足够

## 7. 错误处理

- API 错误（Key 无效 401 / 欠费 402 / 限流 429 / 网络失败）→ 消息区红色错误条 + 重试按钮
- 视觉模型不可用（400 图片不支持等）→ 明确提示"当前模型不支持图片"
- 截屏失败 → 输入框提示，不阻塞文本发送
- 桌宠未运行/助手未启动 → 正常聊天，跳过联动，静默降级
- 助手异常退出 → 主进程记录日志，可自动重启（最多 3 次），不影响聊天

## 8. 测试策略

- 自动化（vitest）：存储读写/迁移、情绪标记解析、SSE 流解析、模型路由决策
- 手动验证（真实环境）：
  - 启动桌宠 → 助手发送 Alt+I → 确认彩虹脸出现（先做，联动风险最高，最早验证）
  - 点击桌宠 → 聊天框弹出；Esc 收起
  - 带 Key 的完整对话流式输出、截屏消息走视觉模型
  - 桌宠全程不崩溃、不闪退

## 9. 技术栈与依赖

- Electron + electron-vite + React + TypeScript
- 运行时依赖从简：react, react-dom, react-markdown, remark-gfm, highlight.js
- 无原生 Node 模块；DeepSeek 调用用内置 fetch，不引入 SDK
- 打包：先以开发模式运行（`npm run dev`），稳定后再用 electron-builder 打 Windows 安装包（可选里程碑）

## 10. 风险与验证顺序

| 风险 | 等级 | 对策 |
|---|---|---|
| 全局鼠标钩子在目标机器上不稳定 | 中 | 实现时第一步就用真实桌宠验证；备选方案：轮询鼠标+GetAsyncKeyState 判断点击 |
| 桌宠以管理员运行时 UIPI 阻止按键注入 | 中 | 助手检测桌宠权限后按需 UAC 提升自身（一次） |
| DeepSeek 视觉模型为实验性（exp），可能调整 | 低 | 模型名在设置页可改；路由规则独立可测 |
| 情绪标记偶尔不出现/格式错乱 | 低 | 解析失败→默认表情，绝不影响文本显示 |

**实施顺序（里程碑）**：M1 聊天核心（存储+流式+多会话+Markdown）→ M2 设置页与 DeepSeek 接入 → M3 截屏与视觉模型路由 → M4 桌宠联动（钩子+按键+情绪）→ M5 打包与收尾。M4 的联动验证点提前到 M2 后先做一次冒烟（发送 Alt+I 验证表情），降低最大风险。
